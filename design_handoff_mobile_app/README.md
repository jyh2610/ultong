# Handoff: 멍냥로드 (MeongNyangRoad) 모바일 앱

## Overview
반려동물 동반 여행 앱. 반려동물의 체중/크기/이동장 소지 여부를 등록하면, 관광지·숙박·식당 등 시설별 "실제 입장 가능 여부"를 조건 매칭으로 계산해 3단계(입장가능/조건부가능/확인필요)로 보여준다. 원문 근거 인용, 준비물 자동 체크리스트, 코스 담기, 오프라인 저장, 제보 기능을 포함한다.

## About the Design Files
이 폴더의 `.dc.html` 파일은 **디자인 레퍼런스(HTML 프로토타입)** 다. 실제 프로덕션 코드로 그대로 옮기지 말 것. 목적은 이 설계를 **React Native + 기존 코드베이스의 패턴/라이브러리로 다시 구현**하는 것이다. 코드베이스가 아직 없다면 React Native(Expo 권장)로 새로 세팅.

- `멍냥로드.dc.html` — 앱 본체, 6개 화면 전체 상태/인터랙션 (fake-clickable prototype)
- `멍냥로드 Deck.dc.html` — 발표용 슬라이드 덱 (참고용, 구현 대상 아님)

## Fidelity
**High-fidelity.** 색상, 타이포, spacing, 컴포넌트 형태가 최종 값에 가깝다. 실제 값은 아래 "Design Tokens" 참고. 픽셀 단위로 정확히 맞출 필요는 없지만 색상/타입 스케일/레이아웃 비율은 지켜서 재현할 것.

## Design Tokens
- Primary(강조) 색상: 프로토타입은 tweak으로 4개 후보(`#1F6D52` 녹색, `#0F766E` 틸, `#2563A6` 블루, `#7A4A2B` 브라운) 중 택1 — 최종 선택은 브랜드팀 확정 필요. 기본값 `#7A4A2B`.
- 배경: `#EDE9E1` (프레임 바깥), 화면 배경 `#FAF7F6`
- 텍스트: 기본 `#1C1C1E`, 보조 `#6B6B6E`, 옅은 보조 `#9A9A9E`
- 카드/보더: 배경 `#fff`, 보더 `#EEE9E0` 또는 `#E8E4DC`, radius 14–20px
- 상태 배지: 입장가능 bg `#E3F3E9` / fg `#1F7A45`, 조건부가능 bg `#FDF1DD` / fg `#B4720A`, 확인필요 bg `#F0EFEC` / fg `#6B6B6E`
- 경고(제보 누적) 배지: bg `#FDF1DD`, border `#F0D9A8`, text `#8A5A0A`
- 원문 근거 블록: bg `#FAF8F4`, dashed border `#DDD6C8`, text `#5C5138`
- 폰트: Pretendard (한국어 최적화 산세리프). 본문 13–15px, 타이틀 20–25px, 헤드라인 46–52px(데크 전용)
- 하단 탭바: 활성 아이콘/텍스트 = primary color, 비활성 `#9A9A9E`

## Screens / Views

### 1. 온보딩 (Onboarding)
- 목적: 반려동물 프로필(들) 등록 — 이후 모든 매칭 계산의 기준값 생성
- 레이아웃: 세로 스크롤, 상단 타이틀 + 설명, 반려동물 카드 리스트(반복 가능), 하단 sticky CTA
- 카드 구성: 이름(inline-editable text input), 종(강아지/고양이 토글 버튼), 견종/묘종(text input), 체중 슬라이더(1–40kg, 실시간으로 소형/중형/대형 계산: ≤5kg 소형, ≤15kg 중형, >15kg 대형), 이동장(케이지) 소지 토글 스위치
- "+ 반려동물 추가" 버튼으로 카드 무한 추가, 각 카드에 "삭제" 텍스트 버튼
- CTA: "시작하기" → 홈으로 이동

### 2. 홈 (Home)
- 상단: 인사 문구 + 반려동물 이름, 우측 원형 아바타(이니셜, 클릭 시 마이페이지)
- 검색바(텍스트, placeholder "지역, 시설명으로 검색") → 검색결과 화면
- "내 주변 반려동반 가능 시설 보기" 버튼(위치기반 검색 진입점, 강조 배경)
- 카테고리 가로 스크롤 칩: 🐾 산책 친화, 관광지, 문화시설, 축제/행사, 레포츠, 숙박, 쇼핑, 음식, 교통 — 클릭 시 해당 카테고리로 필터링된 검색결과로 이동
- "우리 아이 조건에 맞는 추천" 가로 스크롤 카드(사진, 상태 배지, 이름·타입, 지역, 제보 누적 시 경고 라인)
- "인기 지역" 4열 그리드 칩(서울/제주/부산/강릉)

### 3. 검색결과 (Search Results)
- 헤더: 뒤로가기, "검색결과 · N곳", 리스트/지도 토글
- 카테고리 필터 칩 가로 스크롤(전체 + 🐾 산책 친화 + 9개 카테고리), 선택 시 강조색 채움
- 상태 요약 라인: 입장가능/조건부가능/확인필요 각각 색상 점 + 카운트
- 지도 모드: placeholder 박스("지도 미리보기 (실제 지도 연동 예정)")
- 리스트 모드: 카드형 리스트 — 썸네일, 이름, 상태 배지, 타입·지역, 최종 갱신일, (제보 누적 시) 경고 라인. 클릭 시 상세로 이동

### 4. 시설 상세 (Facility Detail)
- 상단 대표 이미지(풀블리드) + 뒤로가기 오버레이 버튼
- 카테고리·지역, 이름, 타입, 상태 배지
- (제보 누적 시) 경고 배너: "최근 제보가 누적된 시설이에요 — 방문 전 규정 변경 여부를 다시 확인해보세요"
- 기본정보 카드: 주소, 운영시간, 최종 데이터 갱신일
- **조건 매칭 결과** — 항목별 리스트(체크/X 아이콘 + 항목명 + 확실/추정 신뢰도 라벨): 견종 크기, 체중 제한, 이동장 필수 여부, 목줄 필수 여부, 실내/실외 동반 가능 여부. 반려동물 조건과 시설 조건을 대조해 계산됨(로직은 아래 State Management 참고)
- **원문 근거 인용 블록** — 점선 테두리, 이탤릭, 원문 텍스트를 그대로 인용 (설명 가능성/투명성 어필용)
- 신뢰도 설명 캡션: "확실은 원문에 조건이 명시된 경우, 추정은 원문이 모호해 일반 기준을 적용한 경우"
- 준비물 체크리스트(배변봉투/접종증명서/목줄/이동장 — 시설 조건에 따라 동적 생성), 체크박스 토글 가능
- "실제 규정이 다른가요? 제보하기" 버튼 → 토스트 메시지
- 하단 sticky CTA: "코스에 담기" / "코스에서 제거하기" (토글)

### 5. 내 여행 코스 (Course)
- 담은 시설 수 표시
- 담은 시설 없으면 empty state
- 있으면: 순서 번호 + 카드 리스트(이름, 상태 배지, 타입·지역), 개별 "제거" 버튼
- "통합 준비물" — 담은 모든 시설의 준비물을 중복 제거해 병합한 단일 체크리스트

### 6. 오프라인 보관함 (Offline)
- "기기에 저장" 토글 스위치 + 상태 텍스트("오프라인에 저장됨 · 네트워크 없이 확인 가능" / "아직 저장하지 않았어요")
- 저장된 코스 있으면: 코스 카드 리스트(읽기 전용) + 통합 준비물 체크리스트
- 없으면 empty state: "코스 탭에서 시설을 담으면 여기서 오프라인으로 저장할 수 있어요"

### 7. 마이페이지 (My Page)
- 반려동물 프로필 카드(온보딩과 동일한 편집 UI), "+ 반려동물 추가"
- 계정 섹션: 알림 설정, 데이터 출처 안내, 로그아웃 (리스트 항목, 상세 동작 미정 — 구현 시 팀 확인 필요)

## Navigation / Tab Bar
하단 고정 탭바 4개: 홈 / 코스 / 보관함 / 마이페이지 (온보딩은 탭바 없음, 별도 진입 플로우). 검색결과·상세는 탭 없는 스택 네비게이션(뒤로가기 버튼으로 이전 화면 복귀).

## Interactions & Behavior
- 체중 슬라이더 값 변경 → 소형/중형/대형 즉시 재계산 → 모든 화면의 매칭 결과가 실시간으로 갱신되어야 함 (전역 상태로 관리)
- 코스 담기/제거, 준비물 체크 토글 시 하단 토스트 노출(1.8초 후 자동 소멸)
- 카테고리 "🐾 산책 친화" 필터: 실외 동반 가능 + (관광지 또는 레포츠) 카테고리만 노출하는 커스텀 필터 (단순 카테고리 매치가 아님)
- 뒤로가기: 화면 진입 스택을 유지해 이전 화면으로 복귀 (단순 브라우저 back이 아니라 앱 내 네비게이션 스택)

## State Management
전역으로 관리해야 하는 상태:
- `pets: []` — 반려동물 프로필 배열 (id, name, species, breed, weight, hasCage)
- `savedIds: []` — 코스에 담은 시설 id 배열
- `checkedPrep: {}` — 준비물 체크 상태 (항목명 → boolean)
- `offlineSaved: boolean` — 오프라인 저장 여부
- 시설 데이터(현재 8곳, 목업): id, name, category, type, region, address, hours, updated, allowedSizes, weightLimitKg, cageRequired, leashRequired, indoorAllowed, outdoorAllowed, confidence(확실/추정), reportCount, rawText(원문)

**매칭 계산 로직** (`computeMatch(pet, facility)` in 프로토타입):
1. 반려동물 체중 → 크기 분류(소형 ≤5kg, 중형 ≤15kg, 대형 >15kg)
2. 크기가 시설의 `allowedSizes`에 없으면 → hardFail
3. `weightLimitKg` 있고 반려동물 체중 초과 → hardFail
4. `cageRequired`인데 반려동물이 이동장 없음 → hardFail
5. hardFail 있으면 상태 = "확인필요"; hardFail 없고 시설 confidence가 "추정"이면 "조건부가능"; 그 외 "입장가능"
6. 각 판정 항목마다 시설의 confidence(확실/추정)를 그대로 노출

**제보 알림 배지**: `reportCount >= 3`인 시설에 경고 표시 (임계값은 목업 값, 백엔드에서 실제 정책 정의 필요)

**준비물 생성**: 배변봉투+접종증명서는 항상 포함, `leashRequired`면 목줄 추가, `cageRequired`면 이동장 추가. 코스 화면에서는 담은 모든 시설의 준비물 목록을 합집합(중복 제거)으로 병합.

## Data Requirements (실제 구현 시)
프로토타입은 하드코딩된 8개 목업 시설을 쓴다. 실제 서비스는 관광공사 지정 API(반려동물 동반 여행 정보)를 사용해야 하며, 카테고리는 API의 contenttypeid 8종(관광지/문화시설/축제행사/레포츠/숙박/쇼핑/음식/교통)과 일치시킬 것. `confidence`(확실/추정)와 `rawText`(원문 근거)는 백엔드의 텍스트 구조화 파이프라인(예: 형태소 분석 기반 조건 태깅)에서 내려주는 필드로 설계할 것 — 이 두 필드가 앱의 핵심 차별화 지점이므로 API 계약에 반드시 포함되어야 함.

## Assets
- 아이콘: 전부 인라인 SVG(단순 라인 아이콘), 별도 아이콘 폰트/라이브러리 불필요 — RN에서는 react-native-svg 또는 동급 아이콘 세트로 재현
- 이미지: 시설 사진은 현재 placeholder(빈 슬롯) — 실제 이미지는 API 응답의 이미지 URL 사용
- 폰트: Pretendard — RN 프로젝트에 폰트 파일 추가 필요 (https://github.com/orioncactus/pretendard)
